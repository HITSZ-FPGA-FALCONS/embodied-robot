# 接线表（v0.1 草案）

> 状态：**草案，未上板验证** · 2026-09-20
> 依据：`Robot_v0.1_四轮差速方案冻结决定.md` §三 · `ACG720_pinout.md`
> ⚠️ **所有引脚号在查过 `ACG720官方资料/06_硬件图纸/` 原理图之前都不能接线。**

---

## 0. 为什么先画表再接线

接线表不是记录，是**预算**。它回答三个问题：

1. **够不够**——信号数有没有超过 `GPIO0` 的 36 位？
2. **会不会打坏**——有没有 5V 信号要进 3.3V 的脚？
3. **会不会撞**——有没有两个功能抢同一个脚？

这三个问题**必须在插线之前**回答。插上再发现，轻则返工，重则报废 IO 甚至整块板子
（板卡是完赛要寄回的，打坏了很麻烦）。

---

## 1. 电平：这是唯一一条会烧板子的规则

> ## ⚠️ FPGA 的 IO 最高 3.3V。`GPIO0` 的电压档位是 3.3 / 1.5 / 1.8 / 2.5V，**没有 5V**。

| 外设输出电平 | 能否直连 | 处理 |
|---|---|---|
| **3.3V** | ✅ 可以 | 直连 |
| **5V 推挽** | ❌ **绝对不行** | 必须电平转换（TXS0108E / 74LVC245 等） |
| **5V 开漏 + 上拉到 3.3V** | ✅ 可以 | 本身就是 3.3V 摆幅 |
| **5V 开漏 + 上拉到 5V** | ❌ 不行 | 把上拉改到 3.3V |

**接线前必须逐个确认：编码器输出是 3.3V 还是 5V？** 见 `待确认问题.md` §三。

> **大多数光电/霍尔编码器模块是 5V 供电、5V 输出。** 这是本项目**最可能烧板子的一条路径**。
> 拿到编码器先用万用表量输出高电平，再接 FPGA。

### 共地

**所有外设必须和 FPGA 共地。** 只接信号线不接地，是最典型的"时好时坏"来源。

> ⚠️ 但**电机大电流的回流不能走信号地**。电机驱动的地要单独走粗线回电池负极，
> 信号地在这条线上**单点汇合**。否则电机换向的电流尖峰会把 FPGA 的逻辑地抬起来，
> 表现就是"电机一转，FPGA 就复位"。

## 2. 信号预算

| 用途 | 信号数 | 必要 | 说明 |
|---|---|---|---|
| 编码器 A/B 相 × 4 路 | **8** | 必须 | 架构决定 §三「做法 2」：四路都读，控制仍按左右两侧 |
| 电机 PWM / DIR × 2 侧 | **4** | 必须 | 两侧各一路 PWM + 一路 DIR |
| 激光雷达串口（M10） | **2** | 必须 | FPGA RX ← 雷达 TX，FPGA TX → 雷达 RX |
| IMU | **2** | 必须 | 见 §4 说明 |
| **小计** | **16** | | |
| 预留（第二路串口 / 调试 / 扩展） | **4** | — | 不许占满，留调试余量 |
| **合计** | **20 / 36** | | `GPIO0` 够用，余 16 位 |

**结论：引脚数够。** 这条在架构冻结决定里已经判断过，此处复核通过。

## 3. 引脚分配（草案）

**从 `GPIO0_18` 起连续分配，避开 `GPIO0_2`~`GPIO0_17`。**

> 为什么避开低段：`ACG720_pinout.md` 指出 Gowin 的 AD7606 例程用到
> `A19/A18/F14/A15/F13/C13~B16` 一段，而**这些脚同时引到扩展口和板载 AD7606 焊盘**。
> 复用关系未查原理图确认，**先用高段最省事**。

| 信号名 | GPIO0 | FPGA 管脚 | 方向 | 电平 | 去向 |
|---|---|---|---|---|---|
| `enc_a[0]` | GPIO0_18 | `D17` | I | 3.3V | 左前编码器 A |
| `enc_b[0]` | GPIO0_19 | `C17` | I | 3.3V | 左前编码器 B |
| `enc_a[1]` | GPIO0_20 | `E16` | I | 3.3V | 左后编码器 A |
| `enc_b[1]` | GPIO0_21 | `D16` | I | 3.3V | 左后编码器 B |

### 命名与约束文件的对应

`.cst` 里的名字必须和上表**完全一致**，否则约束不生效且不一定报错。

```tcl
// 向量信号要逐位绑定，位号与上表一致
IO_LOC  "enc_a[0]" D17;  IO_PORT "enc_a[0]" IO_TYPE=LVCMOS33 PULL_MODE=UP;
IO_LOC  "enc_b[0]" C17;  IO_PORT "enc_b[0]" IO_TYPE=LVCMOS33 PULL_MODE=UP;
// ... enc_a[1..3] / enc_b[1..3] 同理

// 单根信号直接绑
IO_LOC  "pwm_l"    F16;  IO_PORT "pwm_l"    IO_TYPE=LVCMOS33 DRIVE=8;
IO_LOC  "dir_l"    E17;  IO_PORT "dir_l"    IO_TYPE=LVCMOS33 DRIVE=8;
```

> `enc_a` / `enc_b` 在 RTL 里是 `input wire [3:0]`（见接口表 §3.2），
> 位序定义为 **bit0=左前 / bit1=左后 / bit2=右前 / bit3=右后**。
> 这个顺序写死在约束文件里，**RTL 里不要再改**，否则接线表就和实际对不上了。

> **输入为什么 `PULL_MODE=UP`？** 编码器没插 / 断线时，输入脚会浮空并乱跳，
> 计数器会疯狂累加。上拉让"没接"表现为稳定的高电平。
> **输出为什么 `DRIVE=8`？** 默认驱动能力较小，长排线 + 高 PWM 频率下边沿会变缓。

## 4. 三个需要解释的选择

### 4.1 为什么 IMU 不复用板载 I²C（`M16`/`M13`）？

板载 I²C 是**板上已有的总线**，上面挂了什么器件、有没有上拉、上拉到几伏——
都还没查原理图（`ACG720_pinout.md` 明确列为待确认）。

把 IMU 接到一条**状态未知的共享总线**上，出问题时有三种可能的原因，很难区分。
先用两根干净的 `GPIO0` 做独立 I²C，**把变量降到最低**。

> 后面确认板载总线是空的、而且上拉到 3.3V，再考虑搬过去省两个脚。

### 4.2 为什么 PWM/DIR 只占 4 个脚而不是 8 个？

按架构决定 §三，v0.1 **按左右两侧控制**，同侧两个电机的驱动板共用一路 PWM/DIR。

**升级路径已经留好**：将来要做四轮独立闭环，只需把 `pwm_l` / `dir_l` 拆成
`pwm_lf`/`pwm_lr`、`dir_lf`/`dir_lr`，占用 GPIO0_34/35 加两个预留位，**其余不动**。

### 4.3 为什么编码器 4 路都接，但只做两侧控制？

架构决定 §三的结论：**不要把两个编码器的数字输出直接电气并联。**
四路都读回来，既能做左右两侧的反馈，也能顺手做**一致性检查**——
同侧前后轮读数差异过大，通常意味着机械卡滞或编码器故障。

这部分在 FPGA 里只是四份并行的计数逻辑，**不增加控制层复杂度**。

## 5. 上电前检查清单

**第一次给整机上电时，按顺序做，不要跳步：**

- [ ] 万用表确认所有外设信号线**静态电平 ≤ 3.3V**（尤其是编码器）
- [ ] 确认所有外设与 FPGA **共地**
- [ ] 确认电机驱动的电源地和信号地**单点汇合**，没有形成回路
- [ ] **先不接电机**，只上 FPGA，用 IDE 的 Programmer 扫描 JTAG，确认板子活着
- [ ] 烧一个**只有点灯**的 bitstream，确认 LED 正常
- [ ] 只接 **1 个编码器**，手转轮子，用一个把 `enc_*` 直通到 LED 的 bitstream
      确认电平在跳变（**这是验证电平是否安全的最后一道保险**）
- [ ] 确认无误后再接齐 4 个编码器
- [ ] 接驱动板，**电机先悬空不装轮子**，给 10% 占空比确认转向和调速正常
- [ ] 最后才整车通电

> ⚠️ **不要一次接齐再上电。** 一次接齐，出问题时无法定位是哪一路；
> 而且如果有 5V 信号，四路一起上就是四倍的损坏面积。
