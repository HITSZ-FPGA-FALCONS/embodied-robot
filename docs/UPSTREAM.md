# 上游代码与第三方资源登记

> 目的：任何不是本队自己写的东西，都要能回答「它从哪来、什么许可证、我们改了哪里、为什么用它」。

## 为什么要记这个

1. **参赛合规**：作品提交与答辩时，评委可能问「这部分是你们做的吗」。有登记就能当场说清边界。
2. **许可证风险**：GPL / 商业限制条款的代码如果混进最终交付物，后期很难拆。
3. **可复现**：上游仓库会更新、会删分支。只记仓库名不记 commit，几个月后你自己也复现不出来。
4. **避免主仓库被上游淹没**：Fork 保留在 Organization 下，主仓库只放真正集成的部分。

## 登记规则

- 官方例程 / 开源项目：**优先 Fork 到 `HITSZ-FPGA-FALCONS` 组织**，保留 upstream 远程，不要整个复制进主仓库。
- 只把最终系统真正依赖的部分合入主仓库，并在下表中登记。
- 记录到 **commit**，不是「master」「最新版」。
- 修改尽量在 Fork 自己的分支里做，便于将来对比上游。
- **不要**把来历不明、没有许可证、或明显是他人课程作业的代码复制进来。
