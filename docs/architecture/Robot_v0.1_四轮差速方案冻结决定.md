# Robot v0.1 四轮差速方案冻结决定

> 当前结论：**正式底盘优先采用成熟四轮差速车模，不再把麦轮作为默认方案；旧阿克曼底盘降级为备选/可复用零件来源。**
>
> 归档：2026-09-19 · 对应 Issue #6（系统架构 v0.1 与接口边界）
> 相关：`hardware/底盘方案三选一.md`（选型对比过程）、`hardware/ACG720_pinout.md`（引脚）

## 一、为什么选四轮差速

核心判断：

> **优先通过选型避开结构性硬约束，把可通过控制、标定和电源设计缓解的问题留给工程实现。**

| 问题 | 性质 | 是否可工程缓解 |
|---|---|---|
| 两轮平台承载空间不足 | 结构性 | 很难 |
| 阿克曼无法真正定点旋转 | 结构性 | 很难 |
| 四轮原地旋转存在滑移 | 工程性 | 可用 IMU、标定缓解 |
| 四电机峰值电流更大 | 工程性 | 可通过驱动/电源留余量解决 |
| 四轮一致性误差 | 工程性 | 可通过同款电机、编码器和标定缓解 |

因此，四轮差速在当前赛题下更符合：

- 定点旋转
- 承载 ACG720、M10、Camera、电池和驱动板
- 视频中的整机稳定性与完整度
- FPGA 实时闭环控制
- 后续自主导航和视觉扩展

---

## 二、四条硬前提

### 1. 买成熟四轮差速套件

不从零自制底盘。

优先：

- 金属/高质量结构件
- 四轮同型号电机
- 电机自带编码器
- 有上下层安装空间
- 有成熟电机驱动方案或配套驱动板
- 尺寸足以容纳 ACG720 + M10 + Camera + Battery

### 2. 电机必须带编码器

目标：

```text
Encoder → FPGA测速 → 闭环控制 → PWM
```

导航不依赖纯开环速度控制。

### 3. 电源与驱动按四电机峰值设计

必须确认单电机：

```text
额定电压
额定电流
启动电流
堵转电流 I_stall
```

总峰值按至少：

```text
4 × I_stall
```

进行驱动与电源能力核算，并留工程余量。

不能默认 TB6612 一定够用。

如果左右两台电机共用一路 H 桥：

```text
单路驱动峰值能力 > 2 × I_stall
```

并需要考虑散热和瞬态电流。

### 4. 导航采用 Encoder + IMU

四轮滑移转向存在天然侧滑，因此：

```text
Encoder → 速度 / 距离
IMU     → 航向修正
M10     → 环境感知 / 后续定位辅助
```

不把纯轮式里程计当成绝对真值。

## 三、FPGA 控制架构：先保持"两侧控制"

四轮不意味着第一版必须做 4 套独立闭环。

第一版可以：

```text
左前电机 ─┐
          ├── Left Side ← 左路 PWM / DIR
左后电机 ─┘

右前电机 ─┐
          ├── Right Side ← 右路 PWM / DIR
右后电机 ─┘
```

FPGA 顶层仍只需要处理：

```text
v_left
v_right
```

即：

```text
目标 v, ω
   ↓
左右轮速映射
   ↓
Left PID / Right PID
   ↓
PWM / DIR
```

### 编码器注意

**不要把两个编码器的数字输出直接电气并联。**

可选做法：

1. 第一版每侧选一个编码器作为闭环反馈；
2. FPGA 同时读取四个编码器，然后每侧做平均/一致性检查；
3. 后续升级为四轮独立闭环。

推荐第 2 种：保留四路编码器采集，但顶层控制仍按左右两侧处理。

这样 FPGA 增加的只是简单并行计数逻辑，不会显著提高系统复杂度。

> **补充（2026-09-19）：引脚与电平核算**
>
> 做法 2 需要 **4 编码器 × 2 相（A/B）= 8 根信号线**，从 `GPIO0`（36 位）引出。
> 引脚数够，但**接线表要提前画**（见 `hardware/` 接线表模板），且必须共地。
>
> ⚠️ **编码器输出电平必须确认为 3.3V。** 5V 直连会打坏 FPGA 的 IO
> —— FPGA IO 最高 3.3V，`GPIO0` 的电压可选档位是 3.3/1.5/1.8/2.5V，**没有 5V**。
> 若是 5V 输出，必须配电平转换。

## 四、驱动器风险

如果采用"两电机共用一路 H 桥"：

```text
Left Driver  → 左前 + 左后
Right Driver → 右前 + 右后
```

优点：

- FPGA 仍只需要两路 PWM / DIR
- 软件和控制模型接近两轮差速

代价：

- 每路驱动器需要承担两个电机的总电流
- 两台电机无法单独调节
- 电机个体差异会表现为前后轮速度/负载不一致

因此驱动器必须根据**实际电机堵转电流**选型，不能先锁死 TB6612、DRV8871、BTS7960 等具体型号。

> **补充（2026-09-19）：前后轮速度不一致是"固有"的，不只是个体差异**
>
> "电机个体差异"这个说法说轻了。更本质的原因是**几何约束**：
>
> ```text
> 转弯时，同侧前后轮行驶的圆弧半径不同
> （前轮在外圈、后轮在内圈）
> ```
>
> 刚性底盘上四个轮子同侧同速（因为左右各并联一路驱动），
> **几何上必然产生侧滑**——这是 skid-steer 的定义性特征，不是"电机不匹配"造成的。
>
> **推论**：不要试图通过"前后轮微调不同速度"来消除它，那反而会增加机械内耗。
> **接受滑移，用 IMU 修正航向。** 这正是硬前提 4 的理由。

本周末先用尺子测：

```text
ACG720 长 × 宽 × 高

接口突出方向
```

同时估计整机需要容纳：

```text

M10

Battery
Motor Driver

```

> **四轮大平台不只是"更好看"，而是机械上更合理甚至必要。**

## 六、旧阿克曼方案降级

如果直接购买成熟四轮差速套件，以下问题不再阻塞主线：

- 旧阿克曼前轮结构
- 后轴是否双电机
- 是否方便改万向轮/自由轮

这些只需要在后续判断：

> **旧车哪些零件可以复用？**

例如：

- 电池
- 电机驱动
- 编码器
- DC-DC
- 接插件
- 机械件

不要因为已经有旧车而产生沉没成本。

## 八、当前冻结方案

```text
成熟四轮差速底盘
+
四个同型号带编码器电机
+
左右两侧速度控制
+
FPGA Encoder / PID / PWM
+
IMU 航向修正
+
M10 360°环境感知
+
前置 Camera
+
ACG720 实时控制核心
```

第一版不追求：

- 麦轮横移
- 四轮独立高级控制
- 完整 SLAM
- 复杂全向运动学

先完成：

```text
直行稳定
→ 后退稳定
→ 普通转向
→ 定点旋转
→ 编码器闭环
→ IMU 修正
→ M10 避障
→ waypoint navigation
```

## 九、里程计标定（补充 2026-09-19）

差速里程计算转角用的是：

```text
ω = (vR − vL) / 轮距
```

> ⚠️ **四轮滑移转向的"轮距"不是物理轮距。**
> 因为轮胎在滑移，实际旋转中心与几何中心不重合，**等效轮距是一个经验值**。

标定方法：

```text
让车原地转 N 圈（建议 ≥10 圈）
记录编码器累计的左右轮位移差 Δs

    有效轮距 = Δs / (2π · N)
```

**实测值与物理轮距常差 10%~30%。** 直接用物理轮距计算，导航会产生**系统性偏差**。

标定结果应记入 `docs/test/`，并在更换轮胎、改变载荷分布后重新标定。

## 十、一句话原则

> **软件能补的，让软件和控制去补；机械自由度、安装空间和承载能力这种补不了的问题，在选型阶段直接避开。**
