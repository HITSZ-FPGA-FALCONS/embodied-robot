## 3. Syncthing 注意事项

`D:\HITSZ_FALCONS` 由 Syncthing 在两台机器间同步，**原本没有忽略规则**，
导致 `.git/` 目录也被同步，产生过：

```
.git/index.sync-conflict-...
.git/refs/heads/....sync-conflict-...
.git/COMMIT_EDITMSG.sync-conflict-...
+ 4 个工作区文件冲突
```

**已添加 `.stignore`**，排除：所有 git 仓库、工具链安装目录、安装包、大资料包。
同步量从约 8 GB 降到约 200 MB。

> **用文件同步工具同步 `.git` 是危险的**：index / refs / objects 不是为跨机文件级
> 同步设计的。`git fsck` 当时是干净的，但那是运气。
>
> **约定：代码走 git，不走文件同步。** 两台机器各自 `git clone`，
> 用分支/PR 协作——这正是 `docs/TEAM_WORKFLOW.md` 里已经写了的方式。

## 4. 已验证模块的运行记录

### `clk_div`（2026-09-20 台式机）

```
sim.bat fpga\tb\tb_clk_div.v fpga\rtl\clk_div.v

  [1] 复位期间 tick=0 .......... OK
  [2] tick 出现次数 = 5 (期望 >=5) OK
  [3] 间隔异常次数 = 0 (期望 0)   OK
  [4] tick 宽度 = 1 周期 ........ OK
  [5] 中途复位 tick=0 .......... OK
PASS  clk_div 全部用例通过
```

反向验证（确认测试能判错）：
- 分频比改错 → `[3] FAIL`（间隔 9 而非 10）
- tick 拉宽到 2 拍 → `[3] FAIL` + `[4] FAIL`

综合：GowinSynthesis 100%，27 寄存器 / 49 LUT（DIV=50M 默认值）

### `pwm_gen`（2026-09-20 台式机）

```
sim.bat fpga\tb\tb_pwm_gen.v fpga\rtl\pwm_gen.v
  ...（9 组用例，全部 OK）
PASS  pwm_gen 全部用例通过
```

反向验证：
- `dir_o` 断掉直通 → `[8] FAIL`
- 占空比条件 `<` 改成 `<=` → `[2][4]` 等多项 FAIL

综合：GowinSynthesis 100%

> **反向验证的意义**：证明这个 testbench 在模块真的错了的时候会报 FAIL。
> 一个永远不报 FAIL 的 testbench，和没有 testbench 是一回事。
