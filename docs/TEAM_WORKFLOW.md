# 三人协作规则

## 原则

三个人都需要掌握基本 FPGA / Git / 系统接口，不采用“一个人懂 FPGA，另外两个人完全黑盒调用”的模式。

但每个阶段要有明确负责人，避免所有人同时研究同一件事。

## 建议的责任划分（初版）

> 具体负责人可以根据队员既有智能车经验再调整。

### A：运动控制 / 底盘
- PWM
- 编码器
- 电机驱动
- 单/双轮闭环
- 差速底盘
- 控制参数实测

### B：传感器 / 硬件可靠性
- IMU
- ToF / 超声 / 激光测距
- UART / I2C / SPI
- 电源、接线、接口稳定性
- 故障排查与硬件记录

### C：视觉 / 系统集成 / FPGA-AI 协同
- 摄像头数据链路
- 显示/图像预处理（按实际需要）
- 边缘 AI 接口
- 系统架构
- 顶层集成与数据协议

## 交叉要求

- A 至少能阅读 B/C 的 RTL 接口；
- B 至少能调试基本 PWM/计数器；
- C 至少能独立写简单组合/时序逻辑与 testbench；
- 关键模块不能只有一个人知道如何恢复。

## 每日同步

建议控制在 10 分钟：

```text
昨天完成：
今天要做：
当前阻塞：
需要谁协助：
是否影响接口：
```

不要开成长会议。需要深入讨论的技术问题另开 Issue。

## 接口先行

跨成员协作前，先写接口约定：

```text
模块名称：
输入：
输出：
时钟：
复位：
数据宽度：
有效信号：
单位：
更新频率：
异常状态：
```

## 集成纪律

每次系统集成必须记录：

- 日期；
- Git commit；
- FPGA bitstream 对应 commit；
- 开发板/底盘硬件版本；
- 接线变化；
- 参数；
- 成功/失败现象；
- 视频/波形/日志路径。

模板见 `docs/test/INTEGRATION_TEST_TEMPLATE.md`。

## 决策规则

对“要不要增加一个新功能”先问：

1. 是否直接对应赛题？
2. 是否能提高 FPGA 技术含量、稳定性或演示效果？
3. 是否会破坏当前主链路进度？
4. 最小验证成本是多少？
5. 如果失败，是否能无痛撤回？

如果 1/2 都弱、3 很强，则暂缓。
