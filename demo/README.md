# demo/ — 可复现演示

保存可复现的演示流程、脚本和**现场演示检查清单**。

## 为什么单独列一个目录

校内宣讲把「现场表现」列为评审依据之一，而经验分享里记录过决赛现场的真实故障：蓝牙丢包、电脑异常、供电疑点。**实验室能跑 ≠ 现场能跑**。这里的文件就是用来把「现场能跑」变成一件有准备的事，而不是运气。

## 应放内容

- 演示脚本（按顺序做什么、第几步说什么）
- 现场检查清单（上电顺序、备用线材、备用电源、离线素材）
- 可离线运行的演示版本说明

## 现场演示检查清单模板

### 出发前

- [ ] 演示用 bitstream 已固定在某个 commit / tag，**不是「最新的那个」**
- [ ] 已在**非开发机**上完整跑过一遍全流程
- [ ] 备用线材（电源、USB、杜邦线、摄像头排线）
- [ ] 备用电源 / 充电宝，且确认能带动电机
- [ ] 演示环境与实验室差异已记录（地面材质、光照、无线干扰）

### 到现场

- [ ] 上电顺序确认：先控制，后动力
- [ ] 摄像头画面确认（现场光照可能不同）
- [ ] 地面标记 / 场地尺寸确认
- [ ] 一次完整走通，再开始正式演示

### 出问题时

- [ ] 有明确的「退回安全状态」操作（急停 / 断电）
- [ ] 知道哪些功能可以现场跳过、话术怎么说
- [ ] 不隐瞒未完成的功能，如实说明已完成与未完成部分

## 演示纪律

**不要把「跑通例程」当成完成全部作品来展示。** 已完成与未完成必须如实区分——这既是资料中的明确建议，也是被现场提问时最不容易翻车的方式。
